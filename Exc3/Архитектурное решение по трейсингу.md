# Архитектурное решение по трейсингу

## Системы, которые следует покрыть трейсингом

На данный момент заказ проходит через следующие системы:
- онлайн-магазин
- MES
- CRM
Эти системы необходимо включить в трейсинг.

Через некоторые системы заказ проходит несколько раз в частности это CRM.
В каждой системе заказ может изменить статус, причем несколько раз.
Проблемы могут возникнуть как в в моменте передачи заказа между сервисами, так и внутри какого-то сервиса.
Поэтому требуется отслеживать состояние заказа не только на границах сервисов, но и внутри сервиса.

### Список данных
Стандартный набор данных:
- trace_id
- span_id
- timestamp 
Предметные данные:
- id заказа
- status_id - статус заказа
- modify_by - пользователь или сервис который изменил состояние заказа
- еще дополнительная информация по заказу ...

## Мотивация

На данный момент есть проблема что часть заказов "теряется" где-то в системе.
Информация о невыполненных заказах поступает уже непосредственно от клиентов B2C/B2B, что очень плохо сказывается на общем впечатлении от сервиса.

Трассировка поможет локализовать проблемные места, которые можно будет исправить.
Плюс о проблемах с заказом можно будет узнать до того как о проблемах узнают клиенты и принять меры для решения проблемы.

Метрики:
- локализация узких мест, позволит принять решение по масштабированию или доработке сервиса
- локализация проблемных мест, в которых заказы пропадают по какой-то причине
- повышение лояльности клиентов за счет предотвращения проблемы внутри системы до того как пользователь узнает о проблеме

## Предлагаемое решение

На данном этапе предлагается внедрение в API сервисы "Онлайн магазина", "CRM", "MES" внедрить сбор open telemetry.
Так как технологии используемые в сервисах достаточно развитые и популярные, внедрение трейсинга не должно вызвать больших проблем, есть готовые решения которые позволят упростить внедрение.

Для сбора и анализа трейсинга предлагается развернуть Jaeger с бд Elasticsearch и Grafana для широких возможностей визуализации и нотификации.

## Компромиссы

- трейсинг может не подойти системам где затраты на поддержку инфраструктуры трейсинга и внедрения трейсинга могут перевесить потенциальную пользу
- системы с высокими требованиями к производительности, трейсинг дополнительно добавит нагрузку на систему, что может негативно повлиять на производительность
- в монолитных системах можно обойтись менее затратным вариантом трейсинга, возможно дешевле будет кастомное решение

## Безопасность

- отсутствие в трейсинге конфиденциальных данных
- вход в инструменты просмотре трейсинга по учетным данным сотрудников
- ограничить доступ к системам трейсинга внутри сети, отсутствие возможности входа вне сети системы
- защищенные каналы передачи данных трейсинга
