# Архитектурное решение по логированию

## Необходимые логи
Онлайн магазин:
- INFO - изменения статуса заказа (пользователь, идентификатор, timestamp)
- WARNING - для предупреждения нештатных ситуаций, например задержки на каком-то этапе или подозрительная активность
- ERROR - ошибки, для всех непредвиденных ситуаций

CRM:
- INFO - изменения статуса заказа (пользователь, идентификатор, timestamp)
- WARNING - для предупреждения нештатных ситуаций, например задержки на каком-то этапе или подозрительная активность
- ERROR - ошибки, для всех непредвиденных ситуаций

MES
- INFO - изменения статуса заказа (пользователь/система, идентификатор, timestamp)
- WARNING - для предупреждения нештатных ситуаций, например задержки на каком-то этапе или подозрительная активность
- ERROR - ошибки, для всех непредвиденных ситуаций


## Мотивация
В данный момент компания сталкивается с потерей заказов внутри системы и отсутствием лояльности клиентов по этой причине.
Логирование и нотификация о проблемах позволит предотвращать проблемы до того как о них узнает клиент. Что сильно повысит доверие клиентов.

Метрики:
- лояльность клиентов
- сокращение времени на диагностику проблем разработчиками
- общая стабильность системы
- безопасность, предотвращение действий злоумышленников

Желательно настроить логирование на всех трех сервисах, исходя из технологий которые используются в сервисах внедрение хотя бы на уровне логов API займет небольшие трудозатраты.

В связи с ограниченностью ресурсов предлагается настроить логирование в сервисе онлайн магазина и CRM на уровне API.
А в системе MES предлагается настроить трейсинг, так как в данной системе заказ проходит сразу через несколько статусов.


## Предлагаемое решение

Предлагается внедрить сбор логов с помощью ELK стека.

Политика безопасности в отношении логов предполагает:
- отсутствие в логах чувствительных данных
- передачу логов по защищенному подключению
- доступ к kibana только для сотрудников
- отсутствие внешнего доступа к системе логирования из вне системы

Предлагается следующая политика хранения логов:
- каждая система хранит логи в отдельном индексе
- логи хранятся от 30 дней в зависимости от критичности

## Система анализа логов

Необходимо настроить нотификацию для следующих событий
- проблемы с заказом, которые срочно нужно решить
- подвисание заказа в какой-то из систем
- аномальная активность на API MES и API онлайн магазина
- частые ошибки в каком-то из сервисов
